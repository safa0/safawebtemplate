Launching an on-device IDS pilot doesn’t have to be painful. TinySentinel was built to fit microcontroller budgets without sacrificing accuracy. Here’s a practical path to your first deployment.

## 1) Define the Threat and Constraints
- List critical behaviors to monitor (protocol anomalies, timing shifts, unexpected commands).  
- Capture device limits: flash/RAM budgets, control loop timing, energy envelope.  
- Note regulatory needs (CRA/NIS2) and privacy constraints.

## 2) Select Features and Targets
- Choose telemetry that is cheap to collect locally (packet metadata, counters, timing).  
- Map features to your footprint budget—prioritize those with highest signal-to-size ratio.  
- Pick one or two board SKUs for the pilot to keep scope tight.

## 3) Fit the Model
- Apply quantization/pruning to hit <256 KB footprint goals.  
- Validate accuracy against replayed traffic or sensor traces.  
- Set alert schemas and logging levels for your operators.

## 4) Integrate the SDK
- Add the TinySentinel runtime to firmware; wire in feature extraction and inference calls.  
- Measure latency and energy versus baselines; adjust sampling if needed.  
- Implement failsafes so detection never blocks critical control logic.

## 5) Validate on Hardware
- Run attack simulations and benign load to tune thresholds.  
- Verify offline behavior and delayed sync when connectivity drops.  
- Capture evidence for stakeholders and compliance teams.

## 6) Plan the Rollout
- Start with a limited device group and clear success metrics.  
- Prepare operator runbooks and escalation paths.  
- Schedule model refresh/retuning checkpoints.
